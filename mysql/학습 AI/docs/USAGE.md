# 설치와 사용

[학습 AI 홈](../README.md)

## 준비

- Windows 10 22H2 이상 및 MySQL Workbench 8.0의 Python 3 지원 버전. 실제 연동 확인 환경은 Workbench 8.0.47 / 내장 Python 3.12.11입니다.
- DB 연결에 사용할 MySQL 서버와 사용자 계정. 플러그인은 DB 서버를 설치하지 않습니다.
- [Ollama for Windows](https://ollama.com/download/windows). 설치 뒤 `ollama.exe`가 PATH에 있거나 기본 설치 폴더에 있어야 합니다. [Windows 공식 안내](https://docs.ollama.com/windows)
- RAM 8GB 이상을 권장하며 CPU에서도 실행할 수 있습니다. CPU·GPU와 모델 적재 상태에 따라 대기 시간이 달라집니다. 이 수치는 전체 하드웨어에 대한 성능 보장이 아닙니다.
- 모델 파일 약 1.9GB와 실행기·작업용 여유 공간. 처음 모델을 내려받을 때는 인터넷이 필요합니다.

## 처음 설치

1. GitHub 저장소를 clone하거나 ZIP 전체를 내려받아 압축을 해제합니다. ZIP 내부에서 바로 실행하지 마세요.
2. `mysql/학습 AI/1_설치.cmd`를 실행합니다.
3. 설치기는 현재 사용자의 `%APPDATA%\MySQL\Workbench\modules`에 플러그인과 경로 설정을 복사합니다.
4. 시작기는 전용 Ollama 서버를 `127.0.0.1:11435`에서 시작합니다. 모델이 없으면 `qwen2.5-coder:3b`를 내려받습니다. 일반 Ollama 기본 포트 11434와 구분합니다.
5. Workbench에 작성 중인 SQL을 저장하고 프로그램 전체를 종료한 뒤 다시 실행합니다. 연결 탭만 닫는 것으로는 플러그인이 다시 로딩되지 않습니다.

설정 파일에는 이 폴더의 절대 경로가 들어갑니다. 설치 후 이 폴더를 지우지 마세요. 폴더를 옮겼다면 `플러그인_설치.cmd`를 다시 실행하고 Workbench를 재시작합니다.

배치 파일은 해당 PowerShell 프로세스에만 `-ExecutionPolicy Bypass`를 적용합니다. 시스템 전체 실행 정책이나 Windows 자동 시작을 변경하지 않습니다.

## 한글 요청 사용

1. Workbench의 연결을 열고 SQL 탭을 선택합니다.
2. **Tools → SQL AI → 이 탭에서 자동 생성 켜기 / 끄기**를 선택합니다.
3. 새 줄에 `#한글 요청`을 입력하고 Enter를 누른 뒤 잠시 기다립니다.
4. 삽입된 SQL을 읽고 필요하면 고칩니다. 실행은 Workbench의 기존 실행 버튼으로 직접 합니다.

```sql
#분류별 상품 수와 평균 가격을 구해줘
```

영문만 있는 `#` 주석, SQL 문자열 또는 블록 주석 안의 요청은 자동 생성 대상으로 취급하지 않습니다. 한 번만 생성하려면 요청 줄이나 바로 다음 빈 줄에 커서를 두고 **한글 요청 → SQL 생성**을 선택합니다.

자동 모드는 한 번에 선택한 SQL 탭 하나만 감시합니다. 새 탭에서 다시 켜면 감시 대상이 그 탭으로 바뀝니다. Workbench 재시작 후에는 다시 켜야 합니다. 생성 중 내용·커서·탭·기본 DB가 바뀌면 응답 삽입을 취소합니다. 삽입은 Ctrl+Z로 되돌릴 수 있습니다.

## 본인 DB 사용

왼쪽 **SCHEMAS에서 DB를 더블클릭**한 뒤 **Tools → SQL AI → 현재 DB 테이블 구조 읽기**를 선택합니다. 최대 500개 열의 이름·타입·기본 키 정보를 메모리에 보관하며, 모델 입력에는 최대 16,000자를 넣습니다. 행 데이터는 이 메뉴로 읽지 않습니다.

DB 구조가 바뀌면 다시 읽어야 합니다. 구조는 연결·DB별로 구분되며 Workbench가 종료되면 사라집니다. 읽지 않은 경우 요청 앞의 SQL과 연습용 `products` 테이블을 참고하므로 실제 DB와 다른 SQL이 생성될 수 있습니다.

`예제_매장.sql`에는 연습 DB 생성·변경 SQL이 있습니다. 별도의 연습 환경에서 파일 내용을 먼저 읽고 필요할 때 직접 실행하세요. 설치기는 이를 실행하지 않습니다. `memo` 열은 후속 ALTER TABLE 예제에 등장하며 기본 연습 스키마에는 없습니다.

## 오류 해결

| 증상 | 확인할 내용 |
| --- | --- |
| Tools에 SQL AI가 없음 | 설치기를 실행했는지 확인하고 Workbench 전체를 재시작합니다. 1.0.2는 사용자 정의 메뉴 그룹을 초기화합니다. |
| 메뉴가 비활성화됨 | DB 연결과 편집할 SQL 탭을 엽니다. |
| Ollama를 찾을 수 없음 | 공식 Windows 설치 후 터미널/설치기를 새로 열거나 기본 설치 위치를 확인합니다. |
| 로컬 AI 연결 실패 | `AI_시작.cmd`를 실행합니다. 서버는 기본 11434가 아닌 11435여야 합니다. |
| SQL이 삽입되지 않음 | 자동 모드, 요청 앞 `#`, Enter, 생성 중 편집·커서 이동 여부를 확인합니다. |
| 존재하지 않는 열을 생성함 | DB를 선택하고 구조 읽기를 다시 실행하며 요청에 실제 테이블·열 이름을 명시합니다. |
| 진행 메시지가 안 보임 | Workbench 8.0.47에서 Output 함수가 실패하면 하단 상태 표시줄과 `%APPDATA%\MySQL\Workbench\log\wb.log`를 확인합니다. |

시작기 출력은 이 폴더의 `ai-server.log`, `ai-server-error.log`에 저장됩니다. 최대 생성 요청 대기는 180초입니다. [데이터와 기록](PRIVACY.md)

## 종료와 제거

AI를 사용하지 않을 때는 자동 모드를 끕니다. 서버도 종료하려면 작업 관리자에서 **이 도구로 시작한 ollama.exe 프로세스**를 확인한 뒤 종료합니다. 다른 프로그램이 사용하는 Ollama와 구분하세요.

Workbench 종료 후 아래 두 파일을 제거하면 플러그인이 해제됩니다.

```text
%APPDATA%\MySQL\Workbench\modules\mysql_korean_ai_grt.py
%APPDATA%\MySQL\Workbench\modules\mysql_korean_ai_config.json
```

모델과 실행 로그는 이 폴더에 별도로 남습니다. Workbench 자체의 SQL 이력·자동저장·로그도 별도 파일입니다.
