## 공개 준비 검사 — 2026-11-11

공개 폴더에서 `test_local_ai.py`의 **15개 테스트를 재실행해 모두 통과**했습니다. 모델과 실제 Workbench 없이 실행하는 단위·모의 객체 검사이며, 다음을 확인합니다.

- 한글·이모지 UTF-8 바이트 위치, LF/CRLF 줄바꿈과 요청 아래 삽입
- Enter 전 대기, 문자열·블록 주석을 요청으로 인식하지 않음
- 기존 SQL 보존, 내용·커서·DB·탭 변경 시 오래된 응답 삽입 취소
- 52개 예제 제목에 대한 저장 답안 반환
- Workbench Output 함수 실패 시 삽입을 중단하지 않는 대체 출력
- 사용자 정의 메뉴 그룹 초기화, 세 명령 연결과 중복 등록 방지

52개 예제 제목 검사는 모델 정답률 측정이 아니라 **저장된 예제 반환 경로**의 검사입니다.

실행 방법 — 이 폴더에서:

```powershell
py -3 -m unittest -v test_local_ai
```

설치·시작 PowerShell의 구문 검사도 통과했습니다. 공개본은 원래 휴대용 Ollama 경로와 함께 설치된 `ollama.exe`도 찾도록 보완했습니다. PATH에 실행기를 제공한 상태에서 시작기를 실행해 기존 11435 서버와 모델 확인 경로가 성공하는 것을 확인했습니다. 모델이 없는 새 PC에서의 설치·다운로드 전체는 이번 검사에 포함하지 않았습니다. 이 보완은 기존 사용자 플러그인 설치본이나 모델 파일을 수정하지 않습니다.

## Workbench 연동 기록 — 2026-10-28

환경은 Windows, MySQL Workbench 8.0.47, 내장 Python 3.12.11, MySQL 서버 8.0.46이었습니다.

실제 Workbench 프로세스 안에서 명령 로딩, 수동 생성 SQL 삽입, mforms 타이머 응답 적용, 자동 모드 켜기·끄기, 줄바꿈 이후 생성, 편집 후 삽입 취소, DB 열 메타데이터 조회를 확인했습니다. 생성 SQL은 MySQL에서 실행하지 않았습니다.

발견한 두 오류를 수정했습니다.

| 버전 | 수정 |
| --- | --- |
| 1.0.1 | Windows의 `addToOutput`가 `bad function call` 오류를 낼 때 생성까지 중단되던 문제 수정 |
| 1.0.2 | `pluginMenu='SQL AI'`만 선언해 Tools 메뉴가 누락되던 문제 수정; 초기화에서 실제 메뉴 그룹 생성·연결 |

1.0.2 적용 후 실행 중인 레지스트리에서 `Menu/SQL AI` 그룹의 `SQLEditor` 분류와 세 명령 연결을 확인했습니다. 기존 명령 로딩 검사만으로 화면 메뉴 표시가 검증된다고 볼 수 없다는 점을 반영했습니다.

## 아직 확인하지 않은 범위

- 당시 화면 제어 도구 연결 실패로 실제 마우스 메뉴 클릭과 물리 키보드 Enter 입력 자체는 자동 검증하지 못했습니다.
- 줄바꿈을 실제 편집기 API로 넣어 타이머·삽입을 검증했습니다. 안내 대화상자는 검사 중 기록 함수로 대체한 뒤 복원했습니다.
- 별도 프로필로 시작한 검사도 기존 인스턴스에 전달됐으므로 **완전 종료 후 재시작에 대한 독립 검증으로 계산하지 않았습니다.**
- 원본 웹 SQL 작업실의 MySQL 비교 175건은 이 AI 플러그인의 검사 수에 포함하지 않습니다.

실사용 PC에서는 `1_설치.cmd` 실행 → Workbench 전체 재시작 → DB 연결·SQL 탭 열기 → Tools/SQL AI 확인 → 구조 읽기 → 자동 모드 → 한글 요청·Enter → 삽입 확인 → 생성 중 편집 시 취소 확인 순서로 확인하세요. 처음에는 연습 DB에서 생성 SQL을 직접 검토합니다.
