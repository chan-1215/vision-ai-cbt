## 로컬 모델에 전달하는 내용

플러그인은 한글 요청, 요청 앞 SQL 최대 10,000자, 읽은 DB 구조 최대 16,000자, 연습 예제를 로컬 Ollama 서버로 전달합니다. 엔드포인트는 `127.0.0.1:11435`로 고정되어 있으며 외부 AI API 키를 사용하지 않습니다.

구조 읽기 메뉴는 테이블·열 이름과 타입·키 정보를 조회합니다. 행을 SELECT하지는 않지만, 편집기에 작성한 SQL에 실제 값이 있으면 그 텍스트가 모델 입력에 포함될 수 있습니다. 로컬 처리와 기록 없음은 다른 의미입니다.

시작기는 자식 서버에 `OLLAMA_NO_CLOUD=1`을 설정합니다. 다만 Ollama 설치·업데이트·처음 모델 다운로드는 네트워크를 사용할 수 있습니다. 이 문서는 PC 전체 또는 다른 Ollama 앱의 모든 통신을 보증하지 않습니다.

## 남을 수 있는 기록

| 위치 | 내용 |
| --- | --- |
| Workbench Output·상태 표시줄·`log/wb.log` | 생성 시작·완료 시간, 모델명, 자동 모드 변경, 오류 |
| Workbench `sql_history/` | 사용자가 실행한 SQL과 시간 |
| Workbench `sql_workspaces/` | SQL 탭 자동저장과 작업 공간; 한글 요청 주석이 포함될 수 있음 |
| 이 폴더의 `ai-server*.log` | Ollama 요청 경로·처리 시간·런타임 진단 등; 세부 내용은 실행기 설정·버전에 따라 다름 |
| SQL 파일 | 저장 당시 편집기 내용; 요청 주석이나 생성된 설명이 있으면 함께 저장 |
| `model-check-results.json` | 개발자가 모델 검사를 실행했을 때 합성 요청·SQL·시험 결과 |

Workbench의 Windows 설정 루트는 `%APPDATA%\MySQL\Workbench`입니다. [공식 설정·로그 안내](https://dev.mysql.com/doc/workbench/en/wb-configuring-files.html)

플러그인은 DB에 별도의 AI 사용 이력 테이블이나 AI 작성 표시를 만들지 않습니다. 일반적인 DB 내보내기에 이 PC의 별도 로그가 자동으로 첨부되지는 않습니다. 그러나 SQL 파일의 주석을 지우는 것만으로 자동저장·백업·실행 이력까지 없어지는 것은 아닙니다. DB 서버의 별도 로그 설정은 서버 관리 범위입니다.

## GitHub 공개 범위

소스, 합성 연습 데이터, 사용 설명과 검증 요약만 포함합니다. 실제 서버 로그·사용자 경로 설정·Workbench 작업 공간·개인 DB 데이터·모델 가중치·실행 파일은 포함하지 않습니다. 생성 파일의 실수 커밋을 줄이기 위해 폴더별 `.gitignore`를 제공합니다.
